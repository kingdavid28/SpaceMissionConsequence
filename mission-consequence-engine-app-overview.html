MCE

Mission Consequence Engine

A real-time AI-augmented spacecraft operations dashboard for crewed space missions — combining live sensor telemetry, predictive anomaly detection, emergency procedure guidance, and science mission management in a single progressive web app.

What it is

MCE is a mission control interface designed to run aboard or alongside a crewed spacecraft. It streams live telemetry from all critical spacecraft systems — atmosphere, power, communications, and crew — and uses an AI layer to continuously interpret that data, surface threats before they become emergencies, and recommend the next safest action.

It is built as a Progressive Web App (PWA), meaning it installs directly to any device, works fully offline using cached procedures and sensor defaults, and reconnects automatically whenever the telemetry link is restored. The entire interface is designed for use under stress — monospace data, colour-coded severity levels, and zero-click emergency overlays.

Five operational systems

Life Support — ECLSS

Live O₂ level, CO₂ concentration, cabin temperature, humidity, pressure, N₂ partial pressure, water recovery rate, CO₂ scrubber load, and trace contaminants — all as animated radial and bar gauges updated every second with status thresholds.

Power & Energy

Four-battery state-of-charge with live temperature, voltage, and current. Aggregate main-power gauge, solar array output vs. total consumption, net balance, and a per-subsystem load distribution showing which spacecraft systems are drawing the most power.

Communications

Three communication links (TDRS-East, TDRS-West, Ku-Band, UHF EVA) with live Mbps bandwidth scaled from signal strength. Total available bandwidth rollup, per-service allocation, and four ground station countdowns ticking in real time toward the next AOS window.

Mission & Crew

UTC-driven mission schedule with a live active-event marker. Per-crewmember vitals (heart rate, SpO₂, fatigue %) updated each second. Scientific experiments tracked by priority and status, enriched with real ISS experiment metadata from NASA OSDR.

AI capabilities

  • Threat narrative summary — generates a plain-English 3-sentence mission status brief every 30 seconds, including active alerts, atmospheric readings, and at-risk experiments. Runs on IBM watsonx, OpenAI, or a fully local deterministic engine.
  • Predictive anomaly detection — applies least-squares linear regression to the last 30 seconds of sensor history for 6 sensors (BAT-3 temp, CO₂, O₂, humidity, TDRS-West signal, CO₂ scrubber load). Computes time-to-breach for each threshold and ranks predictions by severity.
  • Crisis decision scoring — when a critical alert fires, the Crisis Panel presents three response options and scores each 0–100 for crew safety using live sensor context (battery temp trajectory, O₂ level, backup reserve, comms signal). Flags the recommended option.
  • Emergency procedure Q&A — crew can ask natural-language questions ("what do I do if CO₂ is rising?") and receive step-by-step procedure answers from a bundled knowledge base covering 7 emergency types. Fully offline — procedures are bundled at build time.
  • Research action recommendation — analyses active experiment status, priority (P1/P2/P3), crew fatigue, and any active system anomalies to recommend the single most important science action for the current shift. Defers science when crew safety is at risk.

NASA open data integration

NASA Open Science Data Repository (OSDR) — experiment metadata is fetched live from osdr.nasa.gov at app load, bringing in real ISS study titles, scientific objectives, and domain classifications (Biology, Plant Science, Physics, Materials Science, Human Research, Earth Observation, Technology Demo). When the API is unreachable the app falls back to a curated offline set of five real published ISS studies including OSD-100 (Rodent Research-1) and OSD-37 (GeneLab Plant Experiment-1), with accurate objectives and direct links back to the OSDR dataset records.

Value for space exploration

Scenario How MCE helps
Communication blackout Offline mode activates automatically. Cached emergency procedures, anomaly detection, and AI scoring continue working with no network. UHF EVA link is preserved as last-resort comms.
Battery thermal runaway BAT-3 temp trend triggers a predictive warning with estimated time-to-breach. The Crisis Panel scores three load-shedding options against live sensor state and recommends the safest one.
CO₂ scrubber nearing depletion Scrubber load bar turns amber and a LiOH canister swap warning appears. AI summary includes the depletion timeline. Crew can ask the procedure Q&A for exact swap steps.
Crew fatigue risk Per-crewmember fatigue accumulates in real time. When any crew member exceeds the warning threshold, the research recommendation switches from "advance experiments" to "prioritise crew rest".
Science prioritisation Experiments are sorted by P1/P2/P3 priority and status. At-risk P1 experiments trigger a red callout and an immediate-urgency research action. The AI brief includes experiment names in the threat narrative.
Multi-system degradation The sidebar alert panel ranks all active alerts by severity and prediction. The AI anomaly panel shows every sensor trend simultaneously so the crew sees the full threat picture at a glance.

Technical architecture

  • React 19 + TypeScript + Vite 8 — compiled PWA, installable on any OS.
  • WebSocket telemetry server — Node.js server emitting 1 Hz sensor packets across 25+ sensor channels. Supports anomaly injection via HTTP POST for training and simulation.
  • TelemetryContext — single React context distributing live sensor state to all tabs simultaneously with automatic reconnection on link loss.
  • AI provider cascade — IBM watsonx → OpenAI → local deterministic engine, selected automatically from environment variables. No API key = fully local, always works.
  • Offline-first — emergency procedures, sensor defaults, experiment baseline, and all UI assets are bundled. The app is fully functional with zero network connectivity.
